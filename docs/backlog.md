# Backlog

Postponed items. One row per item. An item leaves the table when a milestone takes it.

| # | Item | Details | Raised |
|---|---|---|---|
| 1 | Rotation of the master key | Several key versions in the environment and a `casctl` command that re-wraps the data keys ([ADR-4](adr/0004-secrets-encrypted-at-rest.md)). C1 stores `kek_version` and refuses a secret of another version ([SRS — Core](srs/core.md) §3.1) | C1 discovery, 2026-10-04 |
| 2 | Rate budgets per account | The limiter of C1 holds the budgets of a source by name, shared by all its connections. Binance counts some limits per account ([SRS — Binance](srs/exchange-binance.md)). X1 needs none: its four `/sapi` endpoints are IP-limited (X1 D-6, 2026-10-09). X2 decides how a connector declares a budget per account, for the withdrawals and convert endpoints | C1, 2026-10-05 |
| 3 | Warning for a malformed value of `sources.config` | A missing or malformed interval or `stale_after` takes its default silently ([SRS — Core](srs/core.md) §3.1). A log line at start would show a typo | C1, 2026-10-05 |
| 4 | Test hardening | T534 and T628 start `go list` and read `GOFLAGS` of the environment: clear it for the child process. No test covers a failed run reported with the family `unknown`: the fake connector cannot fail the declaration of streams ([test plan C1](test-plan-c1.md) §7) | C1 QA, 2026-10-05 |
| 5 | Intraday rate source | CRS serves one rate per day from every provider; a card quote may use a rate up to three days old over a weekend ([SRS — Card Spend](srs/card-spend.md) §2.1.2). An intraday source is an improvement after the roadmap is finished. CRS keeps the same item in its own backlog (CRS `v0.2.0`, 2026-10-05). Owner's decision of 2026-10-07: a market review of rate providers near the end of the Expense Tracker project; a paid source is possible | S2 discovery, 2026-10-05 |
| 6 | Several `card-auth` instances | The per-card lock and the waiter of a repeated `auth_id` live in memory of one instance ([SRS — Card Spend](srs/card-spend.md) §3.2, §4 issue 6). Needed: a session advisory lock per card and a waiter that polls the row | S2 discovery, 2026-10-05 |
| 7 | Admin operations in a CLI | `setDailyLimit`, `pause` and `unpause` are sent with `cast` and the `ADMIN` key by the Deployment Guide ([SRS — Card Spend](srs/card-spend.md) §3.2). A `casctl` command would remove the dependency on Foundry at run time; the C4 container diagram already shows the CLI with that role | S2 discovery, 2026-10-05 |
| 8 | Tracker state in the database | The time of the last send of an operator transaction, the time of the last failed return attempt and the fees of the last send live in the memory of `card-auth` ([SRS — Card Spend](srs/card-spend.md) UC-3, rules of S2 st6b). After a restart a pending transaction may be replaced early and a failed return retried at once; harmless, but columns on `operator_txs` would make it exact | S2 st6b, 2026-10-06 |
| 9 | Ambiguous commit of a debit outcome | The commit of `APPROVED` (UC-1 step 13) can succeed on the server while the driver returns an error: the processor gets `DECLINED / TIMEOUT`, the row stays `APPROVED` and the tracker confirms the debit, so the card is charged for a declined purchase ([SRS — Card Spend](srs/card-spend.md) UC-1 step 13, D-21). Needed: after a failed commit, a compensating move `APPROVED` → `TIMED_OUT / TIMEOUT` in its own context, so UC-3 rows 4–6 return or decline it | S2 st6b, 2026-10-06 |
| 10 | Operator tools for rare incidents | A nonce of the operator used on chain by a transaction outside `card-auth` leaves its `operator_txs` row for manual handling; no rule says how the row is resolved ([Deployment Guide](deployment-guide.md) §8). A change of the operator key is done by hand: drain, `grantRole` and `revokeRole` with `cast`, edit of the deployment file (§7). Needed: a rule for the row and a `casctl` command for both | S2 st9a, 2026-10-06 |
| 11 | Provider's rate date in the CRS contract | `updated_at` of CRS is the time of its poll and `is_outdated` means a failed poll only, so a provider that serves a file weeks old gives a rate marked fresh ([SRS — Card Spend](srs/card-spend.md) §2.1.2). Needed: the provider's rate date in the CRS contract, so that `card-auth` can refuse an old rate. Work in CRS (owner's decision of 2026-10-07) | S3 discovery, 2026-10-07 |
| 12 | Reconciliation reads the treasury balance itself | Rule 5 of UC-4 reads the stored balance checkpoint of the treasury connection, `balance_checkpoints` ([SRS — Card Spend](srs/card-spend.md) UC-4, S3 D-5). Alternative: the reconciliation reads `balanceOf` of the treasury at `to_block` itself, independent of the completeness check, at the cost of a chain call per run | S3 discovery, 2026-10-07 |
| 13 | Retention of `reconciliation_runs` | Every run is stored ([SRS — Core](srs/core.md) §2.4, S3 D-9): on Base Sepolia a run per tenant at most about every 5 minutes, about 288 a day; none while `finalized` does not move. A retention rule is not specified. Observed on Base Sepolia on 2026-10-08 ([Deployment Guide](deployment-guide.md) §13.6): while the treasury backfills, the worker stores a run after every committed page of the treasury's `logs` stream: 74 runs in 1.5 min, no false mismatch. Option: no run while the treasury `logs` stream is `BACKFILL` | S3 discovery, 2026-10-07; observation S3 st8b, 2026-10-08 |
| 14 | Recovery after a reorg guard hit | A stream stopped by `REORG_BELOW_FINAL` stays failed until an operator acts; no tool exists ([SRS — EVM Connector](srs/evm-connector.md) §4 issue 3). Planned: a CLI command that removes the entries of the connection from the changed block on and resets the cursor. The same case: a local chain restarted under a long-lived database, where a wallet with cards cannot be deleted (EC-114) (S3 D-17) | S3 discovery, 2026-10-07 |
| 15 | A token tracked after connections exist | [SRS — EVM Connector](srs/evm-connector.md) EC-316: the `logs` cursors of the network must be reset to `backfill_floor`. Not built in S3, which tracks one token (S3 D-15) | S3 discovery, 2026-10-07 |
| 16 | Oversized balance of a wallet | Anyone can mint `MockUSDC`: a balance with more than 20 integer digits makes the ledger writer refuse the whole snapshot of the wallet, which stays stale ([SRS — EVM Connector](srs/evm-connector.md) EC-319, S3 D-37). Option: skip such a balance with a count, as EC-315 does for logs; a rule of the engine for every source. A balance checkpoint with such a balance is not returned, so its page is imported (S3 D-39) | S3 st4, 2026-10-07 |
| 17 | Series of `ledger_gap` of a deleted connection | The gauge `ledger_gap{source,connection,asset}` keeps the last value of a deleted connection until `server` restarts ([SRS — Core](srs/core.md) §2.5): a non-zero gap keeps its alert. Needed: remove the series of a connection when it is deleted | S3 st6, 2026-10-07 |
